Automated Donor/Stakeholder Reporting System

Automated the creation of donor reports by integrating Monday.com project updates with OneDrive Excel data, delivering scheduled, customized reports through Azure. This reduced manual reporting time and improved donor transparency.

Technologies: Python | OneDrive | Monday.com API | Azure

Project Story ▶

Problem

The reporting process was chaotic and slow. The communications department had to collect data manually from multiple sources — coordinators, fundraising, and finance — just to compile a single donor report. Each intervention team (education, nutrition, family strengthening, etc.) stored their progress updates separately on Monday.com, while financial allocations lived in Excel or QuickBooks. As a result, donor updates were delayed or forgotten altogether, especially for long-term donors whose contributions went back years.

Context

Because reports depended on manual coordination across departments, teams often disagreed about which clients, families, or interventions were funded by which donor. The lack of centralized visibility caused missed deadlines, inconsistent narratives, and a constant blame game between teams. The organization needed a single automated system that could extract intervention updates, merge them with financial and donor data, and produce clean, ready-to-send reports — without human follow-up.

Action

  • Designed and implemented a Python automation pipeline that directly connects to Monday.com's API to fetch the latest "Report-M&E Experiment" tasks from all intervention boards.
  • Programmed the system to automatically download subitems (text, Word files, and images), clean and standardize them, and merge everything into a predefined donor report template using python-docx.
  • Integrated email automation through Gmail's SMTP to instantly deliver completed reports to the communications and donor relations teams.
  • Added error handling, timestamped file naming, and pagination logic to ensure scalability across 20+ boards and thousands of subitems.
  • Centralized all generated reports in one repository, replacing the fragmented folder system used by departments.

Result

Completely eliminated manual report compilation across departments. Donor reports that used to take 3–5 days are now automatically generated and sent in under 10 minutes. Data inconsistencies and missed donors dropped to zero — every intervention update is now accounted for. The automation brought new transparency to donor tracking, reduced interdepartmental blame, and gave managers clear visibility into which families were supported, by which donor, and in which intervention. Impact review meetings became smoother and more data-driven, as dashboards and reports were available in real time.

QuickBooks → Excel Automation Tool

Built an automated QuickBooks → Excel integration tool that dynamically updates multiple balance sheet schedules in real-time using the QuickBooks API and Excel automation.

Technologies: Python | QuickBooks API | openpyxl | requests

Project Story ▶

Problem

Finance teams at Macheo were manually downloading trial balances and journal entries from QuickBooks and updating more than eight separate Excel balance sheet schedules — for debtors, creditors, prepaid expenses, and cash accounts. This repetitive manual process was error-prone, time-consuming, and often caused version control issues when multiple staff edited the same workbook.

Context

The finance department needed a reliable automation process that could connect directly to QuickBooks, pull journal entries in real-time, and update Excel schedules automatically — without breaking links, overwriting data, or requiring technical intervention from staff.

Action

  • Developed a fully automated QuickBooks → Excel integration tool using Python, requests, and openpyxl.
  • Built a secure OAuth 2.0 token refresh pipeline that retrieves live journal entries from the QuickBooks API.
  • Parsed over 10,000+ journal entry lines per batch using pagination logic, mapped each transaction to the correct Excel sheet (debtors, creditors, prepaid, etc.), and updated the appropriate month column dynamically.
  • Added robust data normalization logic (handling overspends, refunds, and change transactions) and auto-appended missing staff or account entries.
  • Implemented detailed logging and error-handling for full traceability and integrated with Windows Task Scheduler for unattended daily execution.

Result

Eliminated manual data entry across all balance sheet schedules. Financial data now updates automatically each day with zero user input. Month-end report preparation time dropped by over 80%, version errors were eliminated, and accountants can now reconcile all schedules directly from QuickBooks data with full audit transparency.

Power BI Data Centralization Dashboard

Built a centralized Power BI semantic model integrating Azure SQL and Excel sources with automated ETL, row-level security, and real-time dashboards for 30,000+ clients.

Project Story ▶

Problem

Each intervention (Education, Nutrition, Family Strengthening, etc.) maintained separate Excel workbooks and SQL tables with inconsistent client identifiers and reporting formats. Manual merging created constant data conflicts, missing client histories, and contradictory donor figures. Coordination between departments broke down, and accountability for client outcomes became unclear.

Context

Leadership needed a unified, self-refreshing reporting system to consolidate intake, exit, donor, and staff data in one view. The goal was to eliminate manual updates, improve cross-department visibility, and support data-driven impact meetings for over 30,000 clients.

Action

  • Built a centralized Power BI semantic model integrated with Azure SQL and controlled Excel sources.
  • Used Power Query for ETL logic—standardizing column formats, merging duplicate records, and establishing consistent relationships across donor, client, and intervention dimensions.
  • Configured hybrid refresh pipelines combining DirectQuery (for live SQL data) with scheduled imports (for Excel-based datasets) through the Power BI Gateway.
  • Implemented row-level security (RLS) and synchronized refresh schedules via the Power BI Service.
  • Created DAX measures to calculate exit success rates, active client counts, and intervention-level KPIs, allowing dynamic filtering by donor, region, and social worker.

Result

Delivered a fully automated Power BI reporting environment, replacing manual consolidation with real-time, validated dashboards. Report refresh success rose from 60% to 100%, accuracy improved by 90%, and interdepartmental blame over client ownership was eliminated. Coordinators and directors now hold smooth, data-driven impact meetings where visual insights highlight underperforming areas and families needing targeted support.

Exploratory Data Analysis (EDA) with SQL

Conducted SQL analysis on the AdventureWorksDW2022 data warehouse to uncover customer behavior, product performance, and revenue trends using cohort analysis and RFM segmentation.

Technologies: SQL Server | AdventureWorksDW2022 | T-SQL | Window Functions | Joins | Aggregations

Project Story ▶

Problem

The company’s historical sales, customer, and product data were scattered across multiple tables in the AdventureWorksDW2022 data warehouse. Analysts lacked a clear understanding of customer behavior, product performance, and revenue trends, which slowed decision-making and limited actionable insights. Manual analysis was error-prone and inefficient due to the sheer volume of data.

Context

Leadership wanted to identify high-value customers, understand buying patterns, and detect product performance trends to optimize marketing and inventory. The challenge was to provide a comprehensive, repeatable analysis that could be used to inform business strategy without manual aggregation of tables or errors from inconsistent joins.

Action

  • Conducted a full exploratory data analysis using SQL, joining multiple fact and dimension tables.
  • Calculated key metrics like revenue, order counts, and average order values at customer, product, and geography levels.
  • Applied cohort analysis to track customer retention over time and used RFM (Recency, Frequency, Monetary) segmentation to identify top-performing customers.
  • Leveraged SQL window functions for ranking, partitioning, and trend analysis to uncover patterns in product sales and seasonal behaviors.
  • Created reusable queries and visual summaries for management, reducing time for future analyses.

Result

Delivered actionable insights on customer segments, top-selling products, and seasonal revenue fluctuations. Identified high-value customers and opportunities for cross-selling. Enabled data-driven marketing and sales strategies based on solid historical evidence. Saved analysts significant time by creating a set of reusable, standardized SQL queries for ongoing reporting.
